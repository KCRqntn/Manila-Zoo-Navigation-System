# Changes, 26–27 October 2026

## Phones and QR codes
- Every QR code is black on white with a 4-square border and error correction "M"; exhibit codes hold a short
  link (`<public address>/q/MNL-ZOO-…`). Older `/qr-scan?code=…` prints still work.
- Older phones (iOS 15.3 and older) get the 2D map automatically; the 3D map needs newer browsers
  (`artifacts/manila-zoo/src/lib/browserSupport.ts`). Full styling needs iOS 16.4+.
- Refreshing a visitor page opens the welcome window on the website QR code.
- Phone link keeper: `deploy/autostart/phone-link.cmd` → `artifacts/api-server/src/phoneLink.ts` starts the
  Cloudflare link, waits until it works, saves it as the public address (QR codes follow), refreshes the poster,
  and writes `current-phone-link.txt`. The demo shortcut (`start-demo.cmd`) uses it. Not in Windows auto-start
  (that needs your approval: it would publish the site at every sign-in).

## Visitor registration and counting
- The website QR code opens `/visitor-registration`.
- First visit: creates a visitor account (email + password, created confirmed by the server) and registers the group.
- Returning visitors: log in → "Register Your New Visit" with that day's group (companions never carry over).
- Forgotten password: the login form tells the visitor to ask zoo staff. An admin opens Visitor Registrations,
  clicks the visitor's name → "Reset password" and reads out the temporary password (shown once, never stored;
  recorded in the audit log). Staff accounts can't be reset this way; editors and viewers can't use it.
- Each person: age, one category (child < 18, adult 18–59, senior 60+ per RA 9994) and a PWD flag (PWD picked
  from the listed people, so no double counting). Review step before saving; − / + buttons for counts.
- Counted only after the visit and all its people are saved. Duplicate protection: one visit id per form
  (primary key), single request while saving, same account + same group within 30 minutes = same visit,
  per-device rate limits, bot honeypot. A failed first visit removes the new account again.

## Database (migrations in `artifacts/api-server/src/lib/migrations.ts`)
- `2026-10-26-01` visitor_registrations (one row per visit)
- `2026-10-26-02/03` visitor_group_members (one row per person per visit) + commit-time check that members = group size
- `2026-10-27-01` visitor_profiles (one per account, Supabase account id) + visits linked and numbered per account
- All with row-level security; personal data only through the API; admin viewing/export is audited.

## Admin
- Dashboard "Visitors (from registrations)": accounts, visits, person-visits, today, children / adults / seniors /
  PWDs, daily and monthly charts, age distribution.
- Visitors → Visitor Registrations: visit history (visit #n of m, click a name for one visitor's history), CSV export.

## AI Guide
- Answers only the detail asked (habitat, diet, feeding, fun fact, status, size, lifespan, names, exhibit).
- Database-only: world trivia/rankings and off-topic questions refused; unknown animals named; ambiguous names
  ("macaque") get a "which one?" question; the animal list only on explicit request, filterable (endangered, birds…).

## Other fixes
- "Select location" on the map: scrolls the map into view on phones; tapping a pin no longer crashes the page.
- Animal photos: tall photos shown whole or slightly zoomed (list in `AnimalImage.tsx`).

## Data to know about

  counted; the dashboard labels them. Ask for help clearing practice data before collecting real data.
