System architecture

Visitors and staff use the same website. It talks to one API, which keeps all zoo data in a PostgreSQL database on the zoo laptop, asks a separate AI service to read chatbot questions, and uses Supabase only for sign-in and photo storage.

Website

React, TypeScript, Vite, wouter, TanStack Query. 2D map in Leaflet, 3D map in MapLibre GL. A service worker keeps a copy of the map, animals and FAQs for offline use.

API

Express 5 with Drizzle ORM. Checks every admin request against the account's role, logs every change in audit_logs, plans routes along the mapped walkways (Dijkstra), and bumps a map version on each map edit.

AI Guide

A FastAPI service with a fine-tuned bert-base-multilingual-cased model (92.75% accuracy). Answers come from database lookups; low-confidence questions fall back to keyword rules.

Live map updates

Visitor maps poll GET /api/map/version every 30 seconds and reload the places, outlines, walkways and facilities when it changes.

Use cases

Two kinds of people use the system. Visitors use it without signing in; a visitor account adds visit registration, points and rewards. Staff sign in, and their role decides what they can change.

RoleWhat the role can do
DirectorEverything, including creating, deactivating and resetting administrator accounts.
AdminEverything except managing administrator accounts: user roles, audit logs, backups and settings, plus all Editor work.
EditorAnimals, events, announcements, FAQs, games, chatbot training data, the map and QR codes; view and update visitor submissions.
ViewerRead-only: the dashboard, reports, records and submissions.
